# Source audit and mask-composition regression fix

The original JSON constraint work is ncphri's
[PR #3800](https://github.com/Niko1221/Strata/pull/3800), pinned head
`fc2c1ebb7fcc33465d7e2443165112339344b56d`. The tools-plus-JSON extension is
[PR #4222](https://github.com/Niko1221/Strata/pull/4222), pinned head
`ed7f0d1eadbb79912af6aea82afad4e5ee8b443c`. GitHub's read-only API still reported
these heads during this audit; both PRs were open drafts.

The fork's actual merge commit `d09c2747` has upstream `v0.2.11` and #4222 as
parents. #4222 includes the earlier JSON branch through its own history. The
latest #3800 head is a provenance reference in `fork/release.json`, not a second
separately merged parent or an exact ancestor of the fork. The two PR heads have
three JSON-branch-only commits related to later upstream synchronization and
whitespace; this distinction must not be hidden by the provenance list.

The extra persistent name guard, its JSON-mask intersection and the Metal
sampling hook are fork additions. The original contributor must not be blamed
for a failure introduced by that extra integration.

## Finding 1: unsupported schema disables the whole grammar

Reproduced directly against both original PR heads and the fork source, using
llguidance 1.9.1 and the exact frozen array schema:

```text
failed to compile JSON schema: Unimplemented keys: ["uniqueItems"]
```

`Service._with_constraint` catches this error and returns sampling without a
constraint. Therefore **all** masking for that request disappears, including the
otherwise supported minItems=3. Removing uniqueItems only in a separate control
probe makes compilation succeed and forbids `]` after two entries. This is a
root-cause probe, not a proposal to silently remove a requested constraint.

The fallback is already present in the original JSON PR. It is not evidence that
llguidance selectively enforces uniqueness incorrectly: grammar compilation
fails before decoding and the server deliberately falls back.

## Finding 2: the shipped runtime lacks full post-validation

The exact v0.2.11-p1 Control archive has no jsonschema or referencing package.
A dependency-only check of that installed archive's private Python confirmed
`jsonschema_available=false`, `referencing_available=false`, llguidance 1.9.1.
That check ran on atlas without any model or server.

`serve/structured.py` deliberately falls back to `_ObjectOnly` without jsonschema.
An object like `{"values":[1,1]}` therefore passes that fallback. The same local
probe with the full dependency available rejects it. This behavior also exists
in both original PR heads. The optional-dependency design is inherited; the
fork distribution did not add the complete post-validator.

Together these two reproduced code paths explain how the observed array failure
can pass both intended protection layers in the published package. The owner's
live Python module search path was not inspected through SSH, so its exact
installed dependency state is not independently attested.

This review's fix is limited to the mask-width integration error. It does not
add uniqueItems generation support or change the inherited optional-validation
contract. Those limitations remain documented.

## Finding 3: fork-added masks disagreed at word boundaries

The name guard allocates `4 * ceil(vocab_tokens / 32)` bytes. The installed
llguidance 1.9.1 `compute_bitmask()` can return an extra uint32 at exact word
boundaries. A synthetic tokenizer with 320 IDs reproduces the live error without
a model: guard mask 40 bytes, schema mask 44 bytes. At 319 or 321 IDs the widths
agree. The same boundary is reproduced at 288 and 352 IDs.

The old `_intersect` rejected every unequal byte length. Original PR #3800 and
#4222 have no `ToolNameConstraint` class or this intersection; the offending
function was added in fork commit `d09c2747`. Their plain schema masks compute
successfully for the same synthetic vocabularies. The owner's exact model
vocabulary width was not captured; the identical integration error and a
minimal local reproduction establish the failure class, not that unmeasured
model number.

The correction retains the canonical engine width and intersects every real
token ID. Additional complete words cover only IDs outside the tokenizer's
vocabulary and are excluded. The name mask already clears final-word padding.
A schema mask shorter than the real vocabulary or not aligned to uint32 is still
rejected. No unprotected fallback is introduced.

The reference check of
[llama.cpp's llguidance sampler](https://github.com/ggml-org/llama.cpp/blob/master/common/llguidance.cpp)
confirmed token-ID-based mask application and a canonical width derived from the
real vocabulary. Its implementation was used as a reference, not copied or
claimed to have the same Python binding behavior.

## Regression coverage and executed checks

Three new tests in `serve/test_tool_name_constraint.py` use real llguidance masks:

- Boundary and non-boundary vocabularies: 287, 288, 289, 319, 320 and 321 IDs;
  every real token bit equals the intersection, padding stays forbidden.
- A multi-row speculative window retains JSON restrictions, restores the live
  parser state and still permits the genuine EOS after a completed object.
- Truncated or unaligned schema masks are rejected.

Before the correction, the suite ran ten tests with three errors: boundary
subcases at 288/320 and the speculative-window case raised the same mask-width
exception as the Mac. After the correction all ten tests passed. No external
model or service was used for this red/green check.

Original #3800's `serve.test_constrain` plus `serve.test_structured`: **35 passed**.
Original #4222's same two modules: **66 passed**. These are CPU/mock tests of the
unmodified pinned checkouts, not Metal or actual-model validation of either PR.
The fork's previous guard tests used the 262-ID byte vocabulary and never combined
an inner JSON constraint; that coverage missed the word-boundary integration.

Reproduce the audit probes (requires llguidance 1.9.1 and jsonschema in the client
Python environment):

```sh
python3 fork/audit_json_patch.py --source /path/to/pinned/checkout --out /tmp/audit.json
python3 -m unittest serve.test_tool_name_constraint
```

The audit JSON snapshots preserve observations of p1 before the fix. No private
addresses, hostnames, serials, personal paths or credentials are included.
The p2 fix requires a separate owner-managed Mac API rerun before any claim that
the original observed JSON-with-tools failures are resolved on hardware.
