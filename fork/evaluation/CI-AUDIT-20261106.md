## Independent reproduction on the actual PR source

Fresh Python 3.11 environment with only the pinned requirements.txt, matching
that aspect of the Linux workflow. The same five selected tests ran against
PR head 58e44dfe and pristine upstream v0.2.11 c3b3f503.

| Test | Pristine upstream | PR head |
| --- | --- | --- |
| test_ds_parallel.Engine.test_a_request_that_leaves_is_stopped_alone | pass | error |
| test_ds_parallel.Engine.test_requests_at_once_each_their_own_tokens | pass | error |
| test_ds_parallel.Engine.test_the_gen_line_carries_rid | pass | error |
| test_ds_parallel.Engine.test_chat_requests_run_at_once | pass | fail |
| test_server.GpuChoice.test_hip_ordinal | fail | fail |

The four parallel-request regressions belong to this PR relative to upstream.
They must not be dismissed as pre-existing merely because they also occurred
on an earlier fork revision. The fifth test also fails unchanged on upstream
on this host and is a separate baseline/environment finding.

Static cause matching the four reproductions: StrataEngine.generate first
builds GEN/GENI with rid_key, then an added second head assignment discards
rid_key. The existing parallel-engine fixture requires that request identifier.
A fix and a fresh full suite are still needed; this audit makes no claim that
such a fix was applied.
